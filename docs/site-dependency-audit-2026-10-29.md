ESLint remains at 9.39.5 because the latest stable `eslint-plugin-react` 7.37.5 and `eslint-plugin-jsx-a11y` 6.10.2, included by the Next.js configuration, do not declare ESLint 10 support. No peer-dependency checks were disabled. ESLint 9 reached end of life on 2026-08-06; this is an explicit compatibility limitation, not a claim that 9 is the current supported major. Move to ESLint 10 when the bundled plugin set supports it, or evaluate a separate lint configuration migration that retains the existing checks.

Existing major-scoped security overrides remain on their newest compatible maintenance versions. They do not force major releases such as Undici 8 into packages requiring Undici 7. Cloudflare's stable Vite plugin currently depends on its vendor-selected `miniflare` 5 beta runtime; that transitive dependency is retained as published rather than overridden to an incompatible runtime.

## Migrations and verification

- TypeScript 7 has no JavaScript compiler API. Followed Microsoft's documented side-by-side setup: `@typescript/native` aliases `typescript@7.0.2` for `tsc`, while `typescript` aliases `@typescript/typescript6@6.0.2` for API consumers such as typescript-eslint. The compatibility package's `tsc6` reports compiler 6.0.3. This preserves linting while using TypeScript 7 for project checks.
- Next.js invokes the local TypeScript CLI by default. `npm run typecheck` runs `next typegen && tsc --noEmit`: Vite/vinext and Next.js write different route declarations into `.next/types`, so regeneration is required before checking the Next.js validator. Verification includes running this command after the Vite build to cover that ordering regression.
- Cloudflare Vite plugin 1.66 no longer reads `MINIFLARE_REGISTRY_PATH`; migrated to `CLOUDFLARE_DEV_REGISTRY_PATH`, preserving project-local `.wrangler/registry` state.
- Source maps are generated by the current Cloudflare plugin by default; no deploy/upload command was run.

Validated with Node 26.13.0:

```sh
npm ci
npm run lint
npm run typecheck
npm run build:pages
npm run build
npm run typecheck
npm audit
npm audit --omit=dev
```

The Vite static pre-renderer requires a loopback listening socket. It was blocked by the default local sandbox (`listen EPERM 127.0.0.1`) and completed when local build execution was allowed. Vite emits upstream source-map/dynamic-import warnings, and vinext emits Node's `module.register()` deprecation warning; these do not fail the build. Both production build formats and their static routes were generated successfully.

## Security findings

- Full and production npm audits report **0 vulnerabilities** after the lockfile refresh.
- The previous lockfile's Zod 4.4.3 was affected by [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), fixed in 4.6.6. The updated graph uses 4.6.7; current Cloudflare tooling also includes its own patched validator.
- The earlier [braces advisory GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) was withdrawn on 2026-10-23 because the reported issue was not practically exploitable. No fabricated patched braces version or audit suppression was added.
- The [Next.js October 14 security update](https://nextjs.org/blog/nextjs-security-update-october-14-2026) fixes two critical upstream issues and a Server Actions denial of service in 16.4.1. The selected 16.4.3 is newer than that patched version. This project statically exports its public site, but still keeps the framework and build toolchain patched.
