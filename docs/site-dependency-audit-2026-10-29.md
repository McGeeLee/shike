## Migrations and verification

- TypeScript 7 has no JavaScript compiler API. Followed Microsoft's documented side-by-side setup: `@typescript/native` aliases `typescript@7.0.2` for `tsc`, while `typescript` aliases `@typescript/typescript6@6.0.2` for API consumers such as typescript-eslint. The compatibility package's `tsc6` reports compiler 6.0.3. This preserves linting while using TypeScript 7 for project checks.
- Next.js invokes the local TypeScript CLI by default. `npm run typecheck` runs `next typegen && tsc --noEmit`: Vite/vinext and Next.js write different route declarations into `.next/types`, so regeneration is required before checking the Next.js validator. Verification includes running this command after the Vite build to cover that ordering regression.
- Cloudflare Vite plugin 1.66 no longer reads `MINIFLARE_REGISTRY_PATH`; migrated to `CLOUDFLARE_DEV_REGISTRY_PATH`, preserving project-local `.wrangler/registry` state.
- Source maps are generated by the current Cloudflare plugin by default; no deploy/upload command was run.

Validated with Node 26.13.0:

```sh
npm ci
npm run lint
npm run typecheck
npm run build:pages
npm run build
npm run typecheck
npm audit
npm audit --omit=dev
```

The Vite static pre-renderer requires a loopback listening socket. It was blocked by the default local sandbox (`listen EPERM 127.0.0.1`) and completed when local build execution was allowed. Vite emits upstream source-map/dynamic-import warnings, and vinext emits Node's `module.register()` deprecation warning; these do not fail the build. Both production build formats and their static routes were generated successfully.

## Pages compatibility follow-up

The preview for commit `9945f9d9fceccfb6a017948354afe050e3f56c2b` failed before dependency installation: Cloudflare Pages' node-build reported `definition not found: 26.13.0`, including after its plugin retry. GitHub Actions and the earlier local Node 26 builds passed; this was a host runtime-selection failure, not an application build failure.

Use [Node 24.22.1 LTS](https://nodejs.org/en/blog/release/v24.22.1/), the October 21 security release available in the [node-build definitions](https://github.com/nodenv/node-build/tree/master/share/node-build). Node 26.13.0 and the newer 24.22.2 were not yet present there at rollout time. The documented [Pages `.nvmrc` override](https://developers.cloudflare.com/pages/configuration/build-image/) selects 24.22.1 without changing Cloudflare environment variables, credentials, or build targets. Package engines and the lockfile's root metadata allow Node 24.22.1 or Node 26.13.0 and newer; resolved dependencies and integrity values are unchanged.

Site CI runs frozen installation, lint, Vite build, regenerated Next route type checks and static export on both Node 24.22.1 and 26.13.0. The latest exact-head CI and real Pages preview must pass before merging. Node 24.22.1 is an explicit deployment compatibility pin, not a claim to be the newest Node release.
